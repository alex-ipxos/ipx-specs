# Data model: Ops Portal identity provider tenants

This feature adds no database tables. Its "data" is the configuration of each identity provider
environment and the secrets derived from it. Each entity below is one thing an administrator
creates by hand, with the values the verification checklist ([quickstart.md](quickstart.md))
asserts. The platform user record belongs to svc-identity (IPX-9498), not to this feature.

## Tenant (one per environment)

| Field | dev | staging | Rule |
|---|---|---|---|
| name | `ipxos-dev` | `ipxos-stg` | Fixed |
| region | AU | AU | Fixed at creation; the domain ends `.au.auth0.com` (failure mode 12) |
| issuer | `https://ipxos-dev.au.auth0.com/` | `https://ipxos-stg.au.auth0.com/` | Read from the discovery document. Trailing slash included |
| Enable Application Connections | off | off | Set before the application is created (research R2) |
| idle session lifetime | recorded | recorded | Default kept (D6); the value is written in the checklist |
| maximum session lifetime | recorded | recorded | Default kept (D6); the value is written in the checklist |
| custom domain | none | none | ADR-0040 decision 10 |

Production (`ipxos-prd` or similar) is IPX-9504's.

## Application: ipx-ops (Regular Web Application)

| Field | dev | staging |
|---|---|---|
| allowed callback URLs | `https://ops.ipxos.dev/api/auth/callback/auth0`, `https://ipx-ops.localhost/api/auth/callback/auth0` | `https://ops.ipxos.app/api/auth/callback/auth0` |
| allowed logout URLs | `https://ops.ipxos.dev`, `https://ipx-ops.localhost` | `https://ops.ipxos.app` |
| allowed web origins | same as the logout URLs | same as the logout URLs |
| enabled connections | exactly one: the ipxos.ai Google Workspace connection | same |
| client id, client secret | generated by Auth0 → Infisical | generated by Auth0 → Infisical |

## API: svc-identity

| Field | Value (both tenants) |
|---|---|
| identifier (audience) | `svc-identity` |
| signing algorithm | RS256 |
| Enable RBAC | off |
| Add Permissions in the Access Token | off |
| Allow Offline Access | off (no refresh tokens in this feature) |

## Connection: ipxos.ai Google Workspace (enterprise)

| Field | Value |
|---|---|
| strategy | Google Workspace (`google-apps`) |
| Google Workspace domain | `ipxos.ai` |
| Google OAuth client | one per tenant, created in Google Cloud. Redirect URI `https://<tenant>.au.auth0.com/login/callback`, Admin SDK API enabled |
| enabled for | ipx-ops only |

Other connections in the tenant: `Username-Password-Authentication` has **Disable Sign Ups** on and
is enabled for no application. `google-oauth2` (social) is disabled or enabled for no application.

## Action: Restrict to ipxos.ai

| Field | Value |
|---|---|
| trigger | Login / Post Login |
| runtime | Node 22 |
| source of truth | `apps/ipx-ops/auth0/actions/restrict-to-ipxos-domain.cjs` in `ipxos-ai/ipx` |
| behaviour | [contracts/restrict-to-ipxos-domain-action.md](contracts/restrict-to-ipxos-domain-action.md) |
| bound to the Login flow | yes, and it is the only Action in that flow |
| secrets or dependencies | none |

## Secrets (Infisical)

| Location | Key (set by IPX-9500 / IPX-9498; ⚠️ names not fixed here) | Value | Environments |
|---|---|---|---|
| `/web-ipx-ops` | client id | Application client id | dev, staging |
| `/web-ipx-ops` | client secret | Application client secret | dev, staging |
| `/web-ipx-ops` | issuer | Tenant issuer, byte-exact | dev, staging |
| `/svc-identity` | issuer | Tenant issuer, byte-exact | dev, staging |
| `/svc-identity` | audience | `svc-identity` | dev, staging |

svc-identity gets **no** client credentials (ADR-0040 decision 8).

## Lifecycle

```text
tenant created (AU) → flag off → Workspace connection (enabled for no app) → API
→ application (connections: none) → Action deployed and bound → deployed code diffed with the source
→ Workspace connection enabled for ipx-ops (first moment anyone can sign in) → secrets stored
→ checklist run → PASS
```

Any later dashboard change sends the tenant back to "checklist run".
